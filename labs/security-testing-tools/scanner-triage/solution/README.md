# 해설 — 스캐너 리포트 분류

> 스포일러입니다. 직접 풀어 본 뒤에 읽으세요. 이 폴더의 `triage.csv`가 모범 답안, `scope.yaml`이 체크리스트 예시입니다.

## 숫자로 보기
- 리포트 100건 = **38개 문제**(파일·줄·CWE)에 대한 보고. 나머지 62건은 중복입니다.
- 38개 중 진짜 취약점 **17개**, 오탐 **21개**. 오탐 중 2개는 AI 스캐너의 환각(없는 파일, 주석 줄에 없는 코드를 인용)입니다.
- 진짜 취약점은 규칙 기반 도구 두 개와 AI가 모두 보고하는 경우가 많고, 오탐 미끼는 규칙 하나와 AI가 보고합니다. **도구가 많이 보고했다고 진짜인 것은 아니고**, 적게 보고했다고 가짜인 것도 아닙니다.

## 짝으로 읽기 — 같은 CWE, 다른 판정
| CWE | TP (위험) | FP (안전한 이유) |
|---|---|---|
| 89 SQL 주입 | 검색어를 문자열로 이어 붙임 | `$1` 매개변수화 (상품 상세, 주문 수정) |
| 79 XSS | 검색어를 그대로 HTML 출력 | `escapeHtml` 후 출력 / 이스케이프 함수 자체 |
| 639 IDOR | 주문 id 만으로 조회 | `AND member_id = $2` |
| 22 경로 조작 | `path.join(DIR, 입력)` | `path.basename` 으로 경로 제거 |
| 78 명령 주입 | `exec('convert ' + 입력)` | 형식 검사 + 셸 없는 `execFile` |
| 798 비밀 값 | 운영 코드의 JWT 서명 키 | 자리 표시자, 테스트 코드의 시드 비밀번호 |
| 328 취약한 해시 | 비밀번호에 MD5 | 파일 ETag 에 MD5 |
| 338 난수 | 재설정 토큰에 `Math.random` | 추천 순서 섞기 |
| 347 서명 검증 | `none` 알고리즘 허용 | `HS256` 고정 |
| 601 리다이렉트 | `next` 그대로 이동 | 허용 목록 |
| 532 로그 | 비밀번호를 로그에 | 이메일만 |
| 1333 ReDoS | `^(a+)+$` | 길이 제한된 문자 집합 |
| 312 평문 저장 | 카드 번호 전체 | 끝 4자리 |
| 95 eval | 요청 본문을 `eval` | `JSON.parse`, 테스트 코드의 `eval` |
| 918 SSRF | `fetch(입력 URL)` | 고정된 내부 주소 |

TP만 있는 문제: 대량 할당(`Object.assign(order, req.body)` — 상태·금액까지 덮어씀), HttpOnly 없는 세션 쿠키.

## AI 스캐너를 읽는 법
- AI 리뷰는 모든 항목에 "확실합니다", "즉시 수정해야 합니다"라고 씁니다. **확신의 정도는 정보가 아닙니다.** 근거는 코드에만 있습니다.
- 환각 두 건은 `snippet`과 실제 코드를 대조하면 바로 드러납니다. 리포트를 사람에게 넘기기 전에 "인용한 코드가 그 자리에 있는가"를 자동으로 검사하는 것도 좋은 습관입니다.

## 허가·범위 체크리스트
- 보안 테스트는 같은 행동이 허가 여부에 따라 점검도, 침해도 됩니다. 범위를 **글로** 남기고, 범위 밖(하지 않을 것)도 함께 적습니다.
- 대상은 "주소"만이 아니라 "코드 경로"일 수도 있습니다. 이 랩의 대상은 실행되지 않는 샘플 코드입니다.
