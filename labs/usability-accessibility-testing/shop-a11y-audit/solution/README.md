# 해설 — QA 숍 접근성 점검

> 스포일러입니다. 직접 풀어 본 뒤에 읽으세요. 이 폴더의 `tests/`, `triage.csv`, `keyboard-checklist.csv`, `report.csv`가 모범 답안입니다.

## t1 — 자동 스캔
- 결함이 없는 앱에서도 모든 화면에 `region`(랜드마크 밖 콘텐츠)이 나옵니다. 화면 맨 위 실습 안내 띠(`.warning`) 때문인데, 사양서 §10.8이 허용합니다. 이것을 걸러 내지 않으면 테스트가 **언제나** 실패하므로 아무 결함도 구별하지 못합니다.
- 거르는 방법이 중요합니다. `disableRules(['region'])`로 규칙 전체를 끄면 다른 요소의 `region` 위반도 놓칩니다. 모범 답안은 **규칙 id와 요소를 함께** 보고 그 한 건만 거릅니다. 원본 결과는 그대로 저장해 t2에서 사람이 판단합니다.
- 로그인해야 보이는 요소(상단 로그아웃 버튼), 데이터가 있어야 열리는 화면(주문 상세)은 그 상태를 만들어서 스캔해야 합니다. 스캔하지 않은 화면의 문제는 0건이 아니라 "모름"입니다.
- 한 테스트에서 여러 화면을 스캔할 때는 `expect.soft`를 써서 앞 화면이 실패해도 뒤 화면의 결과가 저장되게 했습니다.

## t2 — 분류
| 항목 | 분류 | 이유 |
|---|---|---|
| `image-alt`, `label`, `color-contrast`(재고 글자), `button-name`, `heading-order` | violation | 사양서 §10.1~10.5를 어긴다 |
| `region` (`.warning`) | false-positive | 사양서 §10.8이 허용한다 |
| `color-contrast` (`.promo > p`, incomplete) | needs-review | 배경이 그라데이션이라 axe가 판정을 미뤘다. 색 추출 도구로 확인하면 대비는 충분하다 |

- 같은 문제(상단 로그아웃 버튼)가 여러 화면에 나오면 화면마다 같은 분류여야 합니다.
- 오탐을 위반으로 보내면 개발자는 고칠 필요 없는 것을 고치거나, 다음 보고서를 덜 믿게 됩니다. 그래서 감점합니다.

## t3 — 키보드 점검
- 주문 상세의 "결제하기"는 보기에는 버튼이지만 `div`라서 Tab으로 갈 수 없고 Enter·Space로 누를 수 없습니다. 클릭 처리기만 있는 `div`는 axe가 위반으로 판정하지 못합니다(역할이 없어 "버튼이어야 한다"는 것을 알 수 없음).
- 모든 화면에서 초점 테두리(`outline`)가 지워져 있습니다. 초점은 이동하지만 보이지 않습니다. axe는 초점이 보이는지 확인하지 않습니다.
- 나머지 칸은 pass입니다. 의심만으로 fail을 적으면 거짓 보고로 셉니다.

## t4 — 보고서
- 검사항목 매핑은 `reference/kwcag-2.2.md` 를 따랐습니다. 이름 없는 아이콘 버튼과 제목 수준 건너뜀은 관점에 따라 다른 검사항목으로 볼 수 있어 채점기가 두 검사항목을 모두 받습니다.
- 심각도는 사용자가 핵심 기능을 끝낼 수 있는지로 정했습니다. 키보드로 결제할 수 없는 문제와 초점이 보이지 않는 문제는 `상`, 재고 글자 대비와 배너 이미지는 `하`입니다.
