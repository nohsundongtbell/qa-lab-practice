# qa-lab-practice 비개발자 사용성 테스트

작성: 2026-10-04. 공유 문서판(댓글·편집용)과 내용이 같습니다. 고칠 때는 이 파일을 원본으로 봅니다.

## 테스트 개요

비개발자 한 명이 **위키 안내만 보고** 설치부터 첫 랩 채점까지 해 보는 동안, 진행자가 옆에서 지켜보며 막히는 곳을 기록합니다. 목표는 "참가자가 도움 없이 어디까지 가는가"를 확인하고, 막힌 곳을 위키·README 수정 목록으로 바꾸는 것입니다.

| 항목 | 내용 |
| --- | --- |
| 참가자 | 터미널을 거의 써 본 적 없는 사람 1명 (기획자, QA 입문자 등). 이 저장소를 만든 사람·개발자는 제외 |
| 시간 | 60~90분 (설치 다운로드 시간 포함). 90분이 지나면 그 자리에서 멈추고 끝난 뒤 질문으로 넘어감 |
| 장소 | 참가자 본인 PC (Windows 또는 macOS). 진행자는 옆자리 또는 화면 공유 |
| 시작점 | 저장소 주소 하나만 줌: https://github.com/nohsundongtbell/qa-lab-practice |
| 준비물 | 인터넷, 관리자 권한(프로그램 설치용), GitHub 계정은 필요 없음. 진행자: 이 문서(인쇄 또는 다른 화면), 시계 |
| 따라갈 안내 | 위키 [처음이라면: 설치부터 첫 화면까지](https://github.com/nohsundongtbell/qa-lab-practice/wiki/First-Time-Setup) → [코딩 없이 하는 랩](https://github.com/nohsundongtbell/qa-lab-practice/wiki/No-Code-Labs) |

회사 PC 라 설치가 막혀 있으면 [설치 없이 브라우저에서 하기(Codespaces)](https://github.com/nohsundongtbell/qa-lab-practice/wiki/Codespaces)로 바꿔 진행합니다. 이 경우 GitHub 계정이 필요하고, 과제 2·3 은 "Codespace 만들기"로 대신합니다.

## 진행자 안내

진행자의 일은 돕는 것이 아니라 **막히는 순간을 보는 것**입니다. 도운 곳은 안내가 부족한 곳이므로 모두 기록합니다.

**시작 전 (5분)**

1. 참가자 PC 에 Docker Desktop·Node.js·Git 이 없는지 확인합니다. 이미 있으면 과제 2 의 관찰값이 줄어드니 기록표에 적어 둡니다.
2. 참가자에게 이렇게 말합니다: "시험받는 건 안내 문서이지 당신이 아닙니다. 막히면 그것이 제일 중요한 결과입니다."
3. "하면서 생각나는 것을 소리 내어 말해 달라"고 부탁합니다 (예: "이게 무슨 뜻이지?", "여기를 누르면 되나?").
4. 참가자 동의를 받고 화면 녹화를 켭니다(선택). 녹화하지 않으면 관찰 기록표에 시각을 적습니다.

**진행 중 원칙**

- 참가자가 물어보면 답 대신 "어디서 찾아보시겠어요?"라고 되묻습니다.
- 같은 곳에서 **3분** 넘게 진전이 없거나, 참가자가 포기하려 하면 힌트를 줍니다. 힌트는 작게부터: ① "위키의 어느 단계에 있나요?" → ② 해당 문장 가리키기 → ③ 직접 해 주기.
- 도움을 주면 기록표에 힌트 단계(①②③)와 그 순간의 화면 문구를 그대로 적습니다.
- 표정·한숨·"아"처럼 말로 안 하는 신호도 적습니다.
- 다운로드·빌드를 기다리는 시간은 참가자 잘못이 아니므로 따로 적습니다 ("대기 5분").

**바로 멈추고 진행자가 처리할 것**

- 앱 포트를 공개(Public)로 바꾸려고 할 때 (Codespaces) — 의도적 결함이 있는 앱입니다.
- 비밀번호·개인정보를 입력하려고 할 때, 회사 보안 설정을 바꾸려고 할 때.
- PC 재부팅이 필요할 때 (Docker 설치 중 WSL 2) — 시간만 적고 재부팅 후 이어갑니다.

**끝낼 때**

끝난 뒤 질문을 하고, 참가자가 원하면 `npm run down` 으로 앱을 멈춥니다. 설치한 프로그램은 참가자 것이니 지우지 않습니다.

## 참가자 과제지

이 절만 참가자에게 보여 줍니다. 과제에는 **목표만** 있고 방법은 없습니다. 방법을 위키에서 찾는 것이 테스트입니다.

> 안녕하세요. 오늘은 QA 실습 자료가 처음 쓰는 사람에게 얼마나 쉬운지 보려고 합니다. 아래 주소에서 시작해 과제를 순서대로 해 보세요. 막히면 말씀해 주세요. 막히는 것도 좋은 결과입니다.
>
> 시작 주소: https://github.com/nohsundongtbell/qa-lab-practice

| 과제 | 목표 | 다 됐다는 신호 |
| --- | --- | --- |
| 1. 시작할 곳 찾기 | 시작 주소에서, 나 같은 처음 쓰는 사람이 읽을 안내를 찾아 여세요 | "처음이라면: 설치부터 첫 화면까지" 페이지가 열려 있다 |
| 2. 프로그램 설치 | 안내에 나온 프로그램을 설치하고, 제대로 설치됐는지 확인하세요 | 확인 명령 세 줄에서 모두 버전 번호가 나온다 |
| 3. 실습 자료 받기 | 실습 자료를 내 컴퓨터에 받고, 준비가 됐는지 점검하세요 | 점검 결과 마지막에 "문제 없습니다."가 나온다 |
| 4. 쇼핑몰 열기 | 실습용 쇼핑몰을 띄우고 브라우저에서 열어, 안내에 있는 계정으로 로그인하세요 | 쇼핑몰 화면에 로그인한 이름이 보인다 |
| 5. 첫 랩 채점 | "코딩 없이 하는 랩" 코스의 첫 랩을 시작하고, 첫 과제(t1) 표에 테스트 케이스를 한 줄 이상 더해 채점하세요. 통과하지 못해도 괜찮습니다 | 채점 결과("결과: … 과제 통과")가 나오고, 그 뜻을 참가자가 자기 말로 설명한다 |

과제 5 는 정답을 맞히는 것이 목표가 아닙니다. 채점 메시지를 읽고 다음에 무엇을 할지 아는지를 봅니다.

## 끝난 뒤 질문 (10분)

점수를 먼저 받고, 그다음 열린 질문을 합니다. 점수에는 "왜 그 점수인가요?"를 꼭 덧붙입니다.

**쉬움 점수** — 1(매우 어려움) ~ 7(매우 쉬움)

| 질문 | 점수 (1~7) | 이유 |
| --- | --- | --- |
| 프로그램 설치는 얼마나 쉬웠나요? | | |
| 쇼핑몰을 띄우기까지는 얼마나 쉬웠나요? | | |
| 랩을 시작하고 채점하는 것은 얼마나 쉬웠나요? | | |
| 전체적으로 얼마나 쉬웠나요? | | |

**열린 질문**

1. 가장 당황스러웠던 순간은 언제였나요? 그때 무엇을 기대했나요?
2. 위키에서 무슨 뜻인지 몰랐던 말이 있었나요? (예: 터미널, 저장소, 프로필, 채점)
3. 채점 결과를 보고 다음에 무엇을 해야 할지 알 수 있었나요?
4. 혼자였다면 어디서 포기했을 것 같나요?
5. 안내에서 하나만 고칠 수 있다면 무엇을 고치겠어요?
6. 다음 랩도 해 보고 싶나요? 왜 그런가요 / 왜 아닌가요?

## 결과 정리와 반영

세션이 끝난 날 안에, 막힌 곳을 아래 기준으로 나눠 수정 목록을 만듭니다. 참가자가 2~3명이면 같은 곳에서 몇 명이 막혔는지도 적습니다.

| 심각도 | 기준 | 처리 |
| --- | --- | --- |
| 상 | 힌트 ③(진행자가 대신 함)이 필요했거나 중단 | 다음 테스트 전에 고침 |
| 중 | 힌트 ①②를 받고 성공, 또는 3분 넘게 헤맴 | 다음 번 수정에 포함 |
| 하 | 혼자 성공했지만 망설이거나 말을 오해함 | 모아 두었다가 한 번에 |

막힌 곳 하나마다 다음을 적습니다: 어느 과제에서, 화면에 무엇이 나왔고, 참가자가 무엇을 기대했고, 안내의 어느 문장을 어떻게 고칠지.

**고칠 곳**

- 위키 원본은 저장소의 `docs/wiki/` 에 있습니다 (처음이라면 = `First-Time-Setup.md`, 코딩 없이 하는 랩 = `No-Code-Labs.md`). 위키 화면을 직접 고치지 말고 원본을 고친 뒤 PR 로 합치고 위키에 다시 올립니다 ([`docs/wiki/README.md`](wiki/README.md)).
- 랩 안내는 각 랩 폴더의 `README.md`, 채점 메시지는 각 랩 폴더의 `check/` 에 있습니다.
- Windows 실행 정책 오류처럼 위키에 미확인(`TODO: verify-windows`)으로 남아 있던 항목이 실제로 나왔다면, 그 표시도 확인 결과로 바꿉니다.

수정한 뒤 다른 참가자 한 명으로 같은 테스트를 다시 해서, 같은 곳에서 더 막히지 않는지 확인합니다.
