# 보안 랩 안전 검수 기록

대상: `labs/security-testing-tools/scanner-triage` (랩 11) · 검수일 2026-10-03 · 단계 5의 Opus 체크포인트

이 문서는 보안 랩을 만들 때 정한 **안전 장치와 그 근거**를 남긴다. 장치마다 그것이 깨지면 실패하는 테스트를 함께 둔다(`check/safety.test.mjs`, `check/grading.test.mjs`).

## 1. 결정 사항

| # | 결정 | 이유 | 고정하는 테스트 |
|---|---|---|---|
| S1 | **실행 중인 대상 앱(QA 숍)에 실제 취약점을 추가하지 않는다.** 분석 대상은 랩 안의 실행되지 않는 샘플 코드(`starter/scan-target/`)다 | 앱은 다른 랩들이 함께 쓰고, 학습자 컴퓨터에서 계속 떠 있다. 취약점을 앱에 넣으면 실수로 외부에 노출될 때 실제 위험이 된다. 정적 분석·리포트 분류는 코드만 있으면 된다 | `safety.test.mjs`: 샘플 코드에 `package.json` 없음, 저장소 어디서도 불러오지 않음 |
| S2 | **공격 트래픽을 보내지 않는다.** 채점기·랩 어디에도 페이로드 전송, 스캐닝, 퍼징이 없다 | 이 랩의 레슨은 정적 분석과 리포트 분류다. 동적 스캐닝(ZAP 등)은 2차 후보로 두고, 하게 되면 별도 검수를 거친다 | 채점기는 네트워크를 쓰지 않는다(`requires: [node24]`, `sut_profile: any`) |
| S3 | **가짜 비밀 값은 실제 서비스 형식과 겹치지 않게** 쓴다(`qa-lab-fake-…`) | 실제 형식(AWS·GitHub·Slack 키, 개인 키, JWT)은 비밀 스캐너·푸시 보호에 걸리고, 진짜 유출로 오해되거나 복사되어 쓰일 수 있다 | `safety.test.mjs`: 저장소 전체에서 실제 형식 정규식이 0건 |
| S4 | 샘플 코드가 가리키는 외부 주소는 **루프백뿐**이다 | 학습자가 코드를 따라 해도 외부로 요청이 나가지 않게 | `safety.test.mjs` |
| S5 | **허가·범위 체크리스트(t1)가 통과해야 t2를 채점**한다. 대상은 `127.0.0.1`·`localhost`·`[::1]` 주소와 `labs/security-testing-tools/`·`apps/shop/` 경로만 허용 | "보안 실습은 허가와 범위가 먼저"라는 습관을 채점 흐름에 넣는다. `127.0.0.1.nip.io`, `localhost.evil.test`, `0.0.0.0`, 사설 IP, 저장소 밖 경로(`..`, 절대 경로)는 거절 | `grading.test.mjs`의 범위 안/밖 표 |
| S6 | t2 결과는 **집계만** 출력한다(어떤 id 가 틀렸는지 알리지 않는다) | 항목별로 알려 주면 하나씩 바꿔 보며 정답을 맞힐 수 있다. 판정은 코드로 해야 한다 | `grading.test.mjs`: 출력에 `F-###` 없음 |
| S7 | 리포트의 판정은 **코드로 확인 가능**해야 한다. 인용 코드가 실제 줄과 같고, 환각 항목은 정말로 확인 불가능하다 | 분류의 정답이 출제자의 머릿속에만 있으면 공정하지 않다 | `report-gen.test.mjs` |
| S8 | SonarQube(선택)는 포트를 `127.0.0.1`에만 열고, 기본 계정 비밀번호를 첫 로그인에 바꾸게 안내한다. 토큰은 명령줄에만 쓰고 파일로 저장하지 않는다 | 로컬 도구라도 같은 네트워크의 다른 기기에 열리지 않게 | README 절차 (`TODO: verify` — 개발 환경에서 끝까지 실행하지 못함) |

## 2. 남은 위험과 대응
- **저장소의 코드 스캐닝 경보**: GitHub 코드 스캐닝(CodeQL 등)을 켜면 `scan-target/`이 경보를 만든다. 의도된 샘플이므로 `.github/workflows/codeql.yml` + `.github/codeql/codeql-config.yml` 의 `paths-ignore` 로 제외한다(`scripts/ci/workflows.test.mjs` 가 제외 경로가 실제로 있는지 확인). 기본 설정(default setup)을 쓴다면 저장소 설정에서 같은 경로를 제외해야 한다(`docs/CI.md`). `TODO: verify` — 실제 GitHub 에서 확인하지 못했다
- **학습자가 배운 방법을 허가 없이 쓰는 위험**: README 첫머리에 안전 수칙을 두고, t1 이 동의 항목 4개(내 환경만, 제3자 없음, 실제 데이터 없음, 애매하면 멈춤)를 명시적으로 `true`로 바꾸게 한다. 기술적으로 막을 수는 없으므로 교육으로 대응한다.
- **샘플 코드를 실제 서비스에 복사하는 위험**: `scan-target/README.md`와 모든 파일 첫 줄에 "분석용 샘플 — 실행하지 않음"을 적었다.

## 3. 다음 보안 랩을 만들 때 (예: ZAP 동적 스캐닝, `security-testing-advanced`)
- 대상은 로컬 QA 숍뿐이고, 스캐너 컨테이너는 compose 네트워크 안에서만 앱에 닿게 한다(호스트 포트는 `127.0.0.1`).
- 앱에 취약점을 넣어야 한다면 **결함 카탈로그로만** 넣고(`isDefectOn`), 기본 프로필(`none`)에서는 꺼져 있게 하며, `ALLOW_DEV_TOOLS=1`이 아닐 때는 켤 수 없게 한다.
- 시작 시 허가·범위 체크리스트(이 랩의 `check/scope.mjs`)를 재사용한다.
- 별도 Opus 검수를 거친다.
