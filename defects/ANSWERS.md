# 결함 정답표 (ANSWERS)

> ⚠️ **스포일러.** 랩을 끝낸 뒤 자기 결과를 확인할 때만 연다. 이 문서는 어떤 README에서도 링크하지 않는다.
> 기계용 정의(재현 절차 포함)는 같은 폴더의 `catalog.yaml`이다. 두 파일의 ID 목록은 `npm run validate`가 대조한다.

심각도: S1 치명 · S2 높음 · S3 보통 · S4 낮음

## beginner 프로필

| ID | 유형 | 심각도 | 증상 | 기대 동작 (근거) |
|---|---|---|---|---|
| DF-001 | 경계값 | S3 | 할인 후 금액이 **정확히 50,000원**인데 배송비 3,000원이 붙는다 | 50,000원 **이상**이면 기본 배송비 0원 (SPEC §5) |
| DF-002 | 경계값 | S3 | 누적 구매액이 **정확히 1,000,000원**인 회원이 `GOLD`로 판정된다 | 1,000,000원 이상은 `VIP` (SPEC §1.3) |
| DF-003 | 결정표(조건 조합) | S3 | 등급 할인이 있는 회원은 상품 금액이 최소 주문 금액과 같아도 쿠폰이 `MIN_ORDER_NOT_MET`으로 거절된다 | 최소 주문 금액은 **할인 전 상품 금액(subtotal)** 기준 (SPEC §4) |
| DF-004 | 입력 검증 | S3 | 장바구니 수량 `0`이 받아들여진다 | 수량은 1~99, 위반 시 `400` (SPEC §2) |
| DF-005 | 국제화(한글) | S2 | 한글 이름이 7자만 넘어도 "2자 이상 20자 이하" 오류로 가입이 거절된다 (바이트 수로 셈) | 사람이 보는 글자 수로 2~20자 (SPEC §1.1) |
| DF-006 | 경계값 | S2 | 정률 쿠폰의 최대 할인액이 적용되지 않는다 (89,000원 × 10% = 8,900원 할인) | 할인액은 `maxDiscount`(5,000원)를 넘지 않음 (SPEC §4) |

## intermediate 프로필 (beginner 포함)

| ID | 유형 | 심각도 | 증상 | 기대 동작 (근거) |
|---|---|---|---|---|
| DF-007 | 상태 전이 | S2 | 출고된(`SHIPPED`) 주문이 취소된다 | 취소는 `PENDING`, `PAID`에서만, 그 밖은 `409` (SPEC §7.1) |
| DF-008 | 데이터 정합성 | S2 | 주문을 취소해도 재고가 돌아오지 않는다 (한정 상품이 영구 품절) | 취소 시 재고 복원 (SPEC §7.4) |
| DF-009 | 데이터 정합성 | S2 | 정액(`FIXED`) 쿠폰을 같은 회원이 여러 번 쓸 수 있다 | 발급 쿠폰 1장은 한 번만 (SPEC §4) |
| DF-010 | 숨은 변수(시간대) | S3 | 평일 14:00~23:00(KST)에 결제해도 "당일 출고"로 계산된다 (UTC 기준 시각 사용) | 마감은 KST 14:00 (SPEC §6) |
| DF-011 | 계산(반올림) | S4 | 등급 할인이 반올림되어 1원 더 할인될 때가 있다 (4,990원 × 1% → 50원) | 할인은 원 단위 미만 내림 → 49원 (SPEC §3) |
| DF-012 | 데이터 정합성 | S1 | 쿠폰을 쓴 주문의 **저장된 결제 금액**에 쿠폰 할인이 빠져 있다 (주문 상세의 `total`이 각 항목 계산과 맞지 않음) | `total` = subtotal − 할인 + 배송비 (SPEC §3, §7.2) |

## advanced 프로필 (intermediate 포함)

| ID | 유형 | 심각도 | 증상 | 기대 동작 (근거) |
|---|---|---|---|---|
| DF-013 | API 계약 | S2 | 상품 상세(`GET /api/products/{id}`)의 `price`가 문자열(`"50000"`)이다. 목록은 정상 | `price`는 정수 (openapi.yaml `Product`) |
| DF-014 | API 계약 | S3 | 없는 주문(`GET /api/orders/{id}`)의 404 응답에 `details`가 없다 | 모든 오류는 `code`·`message`·`details` (SPEC §8, openapi.yaml `Error`) |
| DF-015 | API 계약 | S2 | 내 정보(`GET /api/members/me`)에 `totalSpent`가 빠져 있다 | 필수 필드 (openapi.yaml `Member`) |
| DF-016 | API 계약 | S2 | 주문 상세(`GET /api/orders/{id}`)의 `status`가 소문자(`pending`)다. 생성·목록 응답은 대문자 | `OrderStatus` 열거값 (openapi.yaml, SPEC §7.1) |
| DF-017 | API 계약 | S3 | 금액 미리보기에 잘못된 우편번호(`'123'`)를 보내면 `500 INTERNAL_ERROR` | `400 VALIDATION_ERROR` (openapi.yaml `/api/quote` 응답 목록, SPEC §8) |
| DF-018 | 성능 | S3 | 상품 목록(`GET /api/products`)이 요청마다 약 0.5초 걸린다 (DB 연결을 붙잡고 기다림 → 동시 사용자가 늘면 대기열) | p95 100ms 이하 (SPEC §9) |
| DF-019 | 성능(N+1) | S3 | 주문 목록(`GET /api/orders`)이 주문 1건마다 약 80ms씩 느려진다 (주문 수에 비례) | 주문 10건 이하 회원 p95 200ms 이하 (SPEC §9) |

### 웹 화면 접근성 (advanced, `surface: web`)

기본 화면(`v1`) 기준. "도구"는 axe-core 자동 스캔으로 잡히는지(자동) 키보드 수동 점검이 필요한지(수동)다.

| ID | 유형 | 심각도 | 증상 | 기대 동작 (근거) | 도구 |
|---|---|---|---|---|---|
| DF-020 | 대체 텍스트 | S3 | 상품 화면 안내 배너 이미지에 `alt`가 없다 (axe `image-alt`) | 내용이 있는 이미지는 대체 텍스트 (SPEC §10.1) | 자동 |
| DF-021 | 레이블 | S3 | 회원 가입 화면의 우편번호 입력 칸이 레이블과 연결되지 않는다 (axe `label`) | 입력 칸마다 연결된 레이블 (SPEC §10.2) | 자동 |
| DF-022 | 명도 대비 | S4 | 상품 카드의 재고 글자가 흐려 대비가 4.5:1 미만이다 (axe `color-contrast`) | 4.5:1 이상 (SPEC §10.3) | 자동 |
| DF-023 | 이름 | S3 | 로그인 상태의 로그아웃 버튼이 아이콘만 있고 이름이 없다 (axe `button-name`) | 버튼에 접근 가능한 이름 (SPEC §10.4) | 자동 |
| DF-024 | 제목 구조 | S4 | 상품 카드 제목이 `h4`라 `h1` 다음 수준을 건너뛴다 (axe `heading-order`) | `h1` 아래 목록 제목은 `h2` (SPEC §10.5) | 자동 |
| DF-025 | 키보드 | S2 | 주문 상세의 "결제하기"가 `div`라 Tab 으로 갈 수 없고 Enter·Space 로 누를 수 없다 (axe 미검출) | 마우스 동작은 키보드로도 가능 (SPEC §10.6) | 수동 |
| DF-026 | 초점 표시 | S2 | 모든 화면에서 키보드 초점 테두리가 지워져 초점 위치가 보이지 않는다 (axe 미검출) | 초점이 눈에 보임 (SPEC §10.7) | 수동 |

화면 맨 위 실습 안내 띠의 axe `region`(랜드마크 밖 콘텐츠)은 결함이 아니다(SPEC §10.8, 오탐). 상품 화면 안내 배너 글자의 `color-contrast`는 배경이 그라데이션이라 axe 가 판정을 미룬다(incomplete, 수동 확인 필요 — 확인하면 대비 충족).
